# Flux Analyzer

A local, file-based finance variance workbench. Flask/Jinja serves the UI; HTMX polls background jobs and Alpine handles interactions. All financial calculations, formatting, controls and evidence are generated by Python. No database or browser-side AI credentials.

For the comprehensive current FluxSpec v2 engine and all agent steps, parameters, request/response contracts, controls and local API setup, see **[docs/reference.md](docs/reference.md)** and the bundled **/docs** pages. ENGINE_AND_AGENT_GUIDE.md is historical v1 context.

## Run locally

Python 3.10 or later:

```sh
cd flux_analyzer
python -m pip install -r requirements.txt
cp .env.example .env
python app.py
```

Default port is 5000; set `PORT` to change it. In this project, the Flux Analyzer workflow runs the same application. All JS libraries are vendored and require no network access. `pyarrow` is optional: dataset caches use parquet when available, otherwise trusted local pickle caches. Uploaded pickle files are never accepted.

## First analysis

1. Upload CSV/XLSX, or select **Try sample data** (synthetic data clearly labeled).
2. Define each source: exact sheet, header row, column range, role and optional sheet union.
3. Choose a preset and inspect How this flux works.
4. Map columns and choose canonical base/current months.
5. Edit scope, signs, derived fields and lookup joins; review classification.
6. Configure analysis rules and materiality. Valid agent settings auto-apply with an audit log and undo/redo.
7. Run controls, resolve stops, calculate and download the Excel review pack and the FluxSpec setup JSON.
8. Commentary starts as checked deterministic evidence. Generate or edit individual lines and inspect mechanical validation; manually edited business explanations remain unverified.

Two complete, editable example specs are available in **Specs**. The R&M example matches the synthetic ledger and Open PO demo sources; define both first (lookup short name `open_po`). The Benefits example matches `tests/fixtures/benefits.csv`. All of their domain rules live in JSON files under `examples/`.

Mock mode gives generic canned suggestions, not production R&M/Benefits skill behavior. It does not infer business-specific Golden Rules. Those rules belong in approved FluxSpecs and the Equinix agent's skills, never in Python domain branches.

## Connect the Equinix AI Engine

Set `AGENT_MOCK=false` plus `EAP_BASE_URL`, `EAP_AGENT_ID`, `EAP_API_KEY`, and `EAP_PAT` in secure environment settings or a local `.env`. Do not enter credentials into the browser. Live calls have not been verified without access to the corporate endpoint. No substitute AI provider is used.

The client enforces a 50KB encoded envelope cap, bounded samples, request IDs, JSON schemas, repair once for malformed responses, retry for connection/5xx errors only, and background invoke/poll. Logs contain metadata/response only, never headers.

## Specs and arithmetic

The engine has no R&M/Benefits branches. Add agent skills and saved JSON specifications for new analyses. A slice can include months, a scenario and custom filters. Fiscal calendars use `{"calendar":{"start_month":4}}` under `periods`; fiscal labels use the starting year convention (FY26 starts in 2026).

Money is summed with `Decimal` and rounded half-up at output to cents. Driver measures must be additive sums; non-additive mean/ratio/count measures can coexist as supplementary measures. Volume/rate decomposition is defined by measures and a `volume_at_base_rate` configuration.

Expressions use an AST whitelist; there is no eval/exec. Excel text is escaped to prevent uploaded formula injection. CSRF protection and per-browser project ownership protect local work, but this is **not an authenticated multi-user corporate service**.

## Storage and operating limits

Uploads, caches, specs, maps, projects, audit logs and outputs live under `workspace/`, excluded from source control. Sessions use opaque project IDs; clearing a project creates a new project without deleting historical audit files. Saved specs are shared in the local workspace, appropriate for a single trusted local operator.

The worker pool and jobs live in one Python process. Use a single Gunicorn worker with multiple threads. Restarting interrupts pending jobs; completed result files remain. Run metadata-only agent calls in the background. Very large file ingestion/profiling can still take time; CSV parsing over 500MB is chunked but the combined frame must fit in memory.

**Do not publish with real financial data before adding corporate authentication, approved persistent storage, retention policies and a security review.** A hosted filesystem is not guaranteed durable. Local storage is intentional because this prompt explicitly requires it.
